# Ablation — does every field earn its place?

Generated by `python -m demo.ablation`. Each row deletes one field from a record
that supports C2 and re-runs the verifier.

| Field removed | Highest class still supported | What is lost |
|---|---|---|
| `execution.runtime` | none | everything — the record cannot even be replayed as itself |
| `execution.deps_digest` | none | everything — the record cannot even be replayed as itself |
| `execution.path_digest` | none | everything — the record cannot even be replayed as itself |
| `execution.pure` | none | everything — the record cannot even be replayed as itself |
| `predicate.id` | C0 | re-adjudication under any different policy |
| `compared.value` | C0 | re-adjudication under any different policy |
| `policy.resolved_value` | C0 | re-adjudication under any different policy |
| `policy.resolution.provenance` | C0 | re-adjudication under any different policy |
| `candidates.completeness` | C1 | re-adjudication under a *looser* policy |
| `candidates.items` | C1 | re-adjudication under a *looser* policy |
| `action.params_digest` | C2 | **nothing — this field is decoration** |
| `capture.sdk_version` | C2 | **nothing — this field is decoration** |
| `ts` | C2 | **nothing — this field is decoration** |

10 of 13 fields are load-bearing.

The rest are kept deliberately — they carry attribution and human-readable context
for someone reading a run, and §5.1 never consults them. A verifier gating on them
would be claiming evidence it does not have.

## The design law

> **No record carries its own soundness proof.**

Every load-bearing field above exists because some real system omitted it and
nothing in its record revealed the omission.
